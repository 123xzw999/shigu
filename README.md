> 新浪财经数据 + 缠论 + 筹码分布 + 主力行为识别 + 逐板块转折点判断
> 电脑上 `.bat` 双击即用；安卓装 APK。零第三方依赖（纯 Python 标准库 + 原生 JS Canvas）

**下载页（安卓 APK / 使用说明）**：https://123xzw999.github.io/shigu/
**直接下 APK**：https://github.com/123xzw999/shigu/releases/latest

| 平台 | 怎么用 |
|---|---|
| Android | 下载页点「下载识股 APK」→ 允许未知来源 → 安装。首次打开等 3~5 秒 |
| Windows / macOS / Linux | 双击 `启动.bat`（或 `python server.py`），浏览器自动打开 |

> ⚠️ **为什么没有纯网页版。**

> 静态托管（GitHub Pages）只能放介绍页，跑不了真正的分析。
> 安卓版就是把 Python 服务打包进 APK，在手机本地跑，界面用 WebView 加载。

## 它到底做了什么

### 1. 数据层 —— 5 秒一轮的新浪财经抓取

后台线程按 **5 秒**周期抓行情、按 **30 秒**重算深度分析，前端只读缓存，
所以无论开几个页面，对外的请求频率恒定。行情每 5 秒刷新一次，
但缠论/筹码/评分这类重计算 30 秒才跑一遍 —— 既跟得上盘口跳动，又不会把 CPU 和接口打满。

| 数据 | 来源 |
|---|---|
| 实时行情 / 五档盘口 | `hq.sinajs.cn` |
| 指数快照 | `hq.sinajs.cn`（`s_` 简版） |
| 日 / 周 / 月 / 5·15·30·60 分钟 K 线 | `money.finance.sina.com.cn` `getKLineData` |
| 行业板块 | `vip.stock.finance.sina.com.cn/q/view/newSinaHy.php` |
| 场外基金净值 / 基本信息 | `stock.finance.sina.com.cn/fundInfo` |
| 外围市场（美股/港股/外汇/商品） | `hq.sinajs.cn`（`gb_` / `rt_hk` / `fx_s` / `hf_` / `nf_` / `int_`） |
| 美股日线 | `US_MinKService.getDailyK`（指数用 `.DJI/.IXIC/.INX`） |
| 港股日线 | `HK_MinlineService.getMinline`（多日分时聚合成日K） |
| 国际期货日线 | `GlobalFuturesService.getGlobalFuturesDailyKLine` |
| 流通股本（算换手率用） | `qt.gtimg.cn`（仅此一个字段） |

### 2. 指标层 —— 对齐两个开源项目

`core/indicators.py` 是纯 Python 实现的指标内核，命名与默认参数对齐 **pandas-ta**（v0.3.14b），
指标分组与「多指标共振」思路对齐 **srl-python-indicators**：

```
均线族    sma / ema / wma / rma / dema / tema
动量族    rsi / stoch / kdj / willr / cci / mfi / roc / trix / ao / uo
趋势族    macd / adx(+DI/-DI) / supertrend / aroon / donchian / keltner
波动族    bbands / atr / natr / hv
量能族    obv / ad / cmf / vwap / vol_ratio / eom
```

### 3. 缠论层 —— `core/chan.py`

完整链路，不是「画几条折线」：

```
K线包含处理 → 分型 → 笔（老笔标准）→ 线段（特征序列分型）→ 中枢 → 背驰 → 买卖点
```

- **笔**：顶底分型交替，合并K线索引差 ≥ 4，顶必须高于底
- **中枢**：连续三笔重叠，`ZG = min(三笔高点)`、`ZD = max(三笔低点)`，后续笔有重叠则延续
- **背驰**：隔一笔比较同向段的 MACD 柱面积，价格创新高/新低但面积萎缩 ≥ 1.25 倍
- **买卖点**：一买（底背驰）、二买（回调不破前低）、三买（回抽不回中枢），对称有一/二/三卖

### 4. 筹码层 —— `core/chip.py`（本项目的核心）

**CYQ 双层模型**：把历史成交量按价格铺开，再按换手率衰减。

单日筹码用**三角分布**（成交集中在均价附近，不是均匀分布）：

```
f(x) = 2(x-L) / ((H-L)(a-L))      L ≤ x ≤ a
f(x) = 2(H-x) / ((H-L)(H-a))      a < x ≤ H
```

换手衰减：

```
A_t = A_{t-1} · (1 - k·T_t) + V_t · φ_t(x)     T_t 为换手率，k 为衰减系数
```

**主力 / 散户双层分离**是这里最关键的设计。每日的换手筹码按主力参与度拆成两层：

```
m_t = 0.5 + 0.42 · tanh( 0.9(vr_t - 1) + 5·r_t + 1.8(0.5 - p_t) )
```

- `vr_t` 量比、`r_t` 当日涨跌幅、`p_t` 60日价格分位
- 低位 + 放量 + 上涨 → 主力吸筹占比高；高位 + 放量 + 下跌 → 主力派发
- 两层各自独立衰减，并且**用不同的分布核**：主力成交集中在均价（sharp=1.85），
  散户追价铺满区间（sharp=0.42）—— 这样即使比例相同，两个分布在价格上也会分开

由此得到：

- **主力筹码集中区**：主力层分布从峰值向两侧扩展到累计 60% 的价格带
- **散户筹码集中区**：散户层同理
- 主力成本 / 散户成本 / 控盘度 / 获利盘 / 套牢盘 / 90%成本区间 / 集中度 / 成本分离度

另外实现 **Volume Profile（成交量分布）**，对应 srl-python-indicators 的 Volume/TPO Profile：
不衰减地统计历史成交密集区，输出 **POC**（成交峰）与 **价值区 VAH/VAL**（70% 成交量区间）。
它与 CYQ 互补：CYQ 回答「现在谁拿着」，VP 回答「过去在哪反复换手」。

### 5. 主力行为层 —— `core/wyckoff.py`

威科夫量价周期，六个阶段软打分 + softmax：

```
吸筹 → 洗盘 → 拉升 → 派发 → 下跌 ⇄ 横盘
```

每个阶段用 10 个量价特征（位置分位、振幅比、量比、均线排列、上下影占比、OBV 斜率、
收盘位置、最大单日涨跌…）算置信度，避免硬阈值导致阶段跳变。

同时把历史切成阶段片段，算出**每个阶段的成交量加权均价** —— 这就是「该阶段的主力成本」。

### 6. 形态层 —— `core/patterns.py`

覆盖 20+ 种 A 股常见控盘形态，按四组组织：

- **单K**：锤子线 / 上吊线 / 射击之星 / 倒锤子 / 十字星 / 缩量十字星
- **双K**：看涨吞没 / 看跌吞没 / 曙光初现 / 乌云盖顶 / 向上向下跳空
- **三K**：早晨之星 / 黄昏之星 / 红三兵 / 三只乌鸦 / 多方炮 / 空方炮 / 上升三法 / 下降三法
- **主力特化**：涨停板 / 一字板 / 放量洗盘针 / 高位放量长上影 / 岛形反转

### 7. 评分层 —— `core/scoring.py`（自研数学函数）

**TRS · Trend Resonance Score（趋势共振评分）**

七个维度各自标准化到 `[-1, 1]`，再用 `tanh` 软饱和加权：

```
D_i ∈ [-1, 1]                      第 i 维得分
S    = 100 · tanh( κ · Σ w_i D_i / Σ w_i )        κ = 2.2
A    = |Σ w_i D_i| / Σ w_i|D_i|                    共振一致性
Conf = A · (1 - e^(-n/80)) · (0.55 + 0.45·g)      置信度，g 为趋势清晰度
```

**为什么用 tanh 而不是直接加权求和**：原始指标无界（RSI 能到 90，MACD 柱能很大），
线性相加会让某个维度在极端行情下吞掉其他所有维度。tanh 把每个维度压进 `[-1,1]`，
小值区近似线性、大值区饱和，等价于「温和的软阈值」—— 这是本评分与普通打分卡最本质的区别。

| 维度 | 权重 | 输入 |
|---|---|---|
| 趋势 T | 1.25 | 均线偏离、20日回归斜率、ADX 方向 |
| 动量 M | 1.05 | RSI、MACD柱/ATR、ROC、KDJ |
| 量能 V | 0.95 | 量比、OBV 斜率、CMF、量价相关 |
| 筹码 C | 1.15 | 控盘度、成本偏离、集中度、获利盘、吸筹速度 |
| 缠论 L | 1.10 | 买卖点、背驰、中枢位置、走势类型 |
| 形态 P | 0.70 | K线形态加权 |
| 风险 R | 0.60 | 波动率、最大回撤、乖离（负向） |

指数 / 场外基金缺少筹码时，该维度权重自动让给其它维度，不会拉低总分。

输出：评分（-100~+100）、等级、置信度、一致性、七维明细 + 每个维度的文字依据、
关键价位（支撑/压力/止损/目标/盈亏比）、操作建议。

### 8. 转折点判断 —— `core/turning.py`

回答一个问题：**现在是不是趋势的转折点？**

不是靠均线交叉这种粗规则，而是一套在历史数据上标定过的概率模型，
按板块分别训练（银行的反转长相和半导体完全不同）。

#### 8.1 拐点怎么定义（这一步决定了一切）

用 **Pagan-Sossounov 删失局部极值**（Bry-Boschan 风格，金融文献给牛熊分期的标准做法）：

```
1. argrelextrema(price, order=20)        候选局部极值
2. 强制峰谷交替                          同类相邻保留更极端的
3. 删失循环：长度 < 20 根 或 幅度 < 阈值  → 删掉该拐点并与邻段合并
   重复直到所有阶段都合格
```

ZigZag 只有一个幅度阈值，会把「一根大阴线」当成趋势段；PS 同时约束**时间**和**幅度**，
这才是「一段真实趋势」的定义。

#### 8.2 特征（44 维）

| 组 | 内容 | 为什么反转需要它 |
|---|---|---|
| 趋势 6 | EMA 偏离/排列、20 根回归斜率 t 值、ADX | 先判断「现在是什么趋势」 |
| 位置 5 | 60/120 根区间分位、z-score、距 250 日高/低 | 反转只发生在极端位置 |
| 动量 6 | ROC 5/10/20/60、RSI、MACD 柱 | 动量衰减先于价格反转 |
| 量能 5 | 量比、OBV 斜率、量价背离 | 地量见地价；放量才是确认 |
| 波动 4 | ATR%、布林带宽及其分位 | 带宽收窄 = 变盘窗口 |
| 结构 5 | 距创新高/新低天数、实体比、上下影线 | 长下影 = 下方有承接 |
| 背离 3 | 价格 vs RSI / MACD / OBV 方向背离 | 最经典的反转前兆 |
| 力度 3 | 26 根多空力度占比、收盘相对位置 | 借鉴 toroleap 的 ARatio/BRatio |
| **周K共振 7** | 周线 EMA 排列/斜率/位置/RSI/ADX/量比/ROC | 日线背离 + 周线趋势未破 = 高胜率买点 |

**周K 对齐是这里最容易写错的地方**：周K 用自然周聚合，本周要到周五收盘才成立，
所以日K 在任意一天只能用**上一周**的周K 值。不做这一步，模型会在周三「看到」周五的收盘价 ——
回测漂亮，实盘全废。

#### 8.3 每个板块一套参数

15 个板块 × 日K/周K × 上/下方向，共 58 套权重 + 阈值，全部离线标定好存在
`data/turning_profiles.json`（纯 JSON，运行时零依赖加载）。

| 资金属性 | 板块 | 标注幅度 | 特征倾向 |
|---|---|---|---|
| trend 抱团 | 金融、家电、酿酒 | 12% | 趋势延续强，反转需更强确认 |
| cycle 周期 | 煤炭、有色、钢铁、机械、农林牧渔、房地产 | 15% | 商品价格驱动，量价特征权重大 |
| growth 成长 | 电子器件、汽车、传媒、电子信息 | 18% | 噪声大假突破多，需更长确认窗 |
| defense 防御 | 食品、生物制药、电力 | 10% | 低波慢趋势，幅度门槛必须降低 |

个股 → 板块：优先查 `data/sector_map.json`（2128 只 A 股代码表），查不到再按名称关键词，
再查不到用同资金属性的平均参数兜底（界面上会标「兜底」，可信度打折）。

#### 8.4 准确率到底多少（不美化）

标定用**按交易日切折的 walk-forward**（训练窗 750 天 → 测试窗 250 天 → 滚动 8 折），
训练永远在测试之前，标准化参数和阈值只从训练窗算。49 个有效组合的样本外结果：

| 指标 | 数值 |
|---|---|
| 平均 precision（命中拐点） | **29.8%** |
| 单组合最高（可信） | **53.3%**（家电·日K·顶部） |
| 随机基线 | 6% ~ 9% |
| 相对基线提升 | **3.5 ~ 6 倍** |

**「每个板块 80%」做不到，而且不打算用调参把它做成假的。**
80% 只有两种凑法：把阈值拉到极端让信号少到个位数（一年发不出一次），
或者把「反转」定义放宽到事后拟合。两种都不做。

但换个口径看，这套东西是有价值的 —— 信号点的**最大浮盈**显著优于随机位置：

| | MFE 中位 | 随机对照 | 超额 | 胜率 | 随机胜率 |
|---|---|---|---|---|---|
| 日K 底部信号 | 24.8% | 7.4% | **+17.4pp** | 79.0% | 35.2% |
| 日K 顶部信号 | 16.8% | 6.6% | **+10.2pp** | 91.5% | 34.1% |

也就是说：**它没法告诉你哪一根是最低点，但能告诉你现在是不是比瞎买好得多的位置。**

#### 8.5 怎么读那两个数字

界面上每行都给两个值：

```
底部反转  0.016  ▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁   分位 31%
顶部反转  0.701  ▇▇▇▇▇▇▇▇▇▇▇▇▇▇▇▏░░░░░░   分位 87%
```

- **概率**：模型输出的绝对概率，条上的细竖线是标定阈值
- **分位**：这个概率在过去 160 根 K 线里排第几。`≥95%` = 近一年最像反转的 5% 时刻

**优先看分位。** 绝对阈值是在某段历史上标定的，换一段时间概率分布就漂了 ——
实测中训练集标到 95% 的阈值，样本外经常一次都不触发；而分位是相对的，稳定得多。

#### 8.6 K线上的标记

K线图上画**空心圆环 + 「顶」/「底」**，是 PS 算法事后确认的拐点（用于复盘校验）。
实心三角留给缠论买卖点，两套信号不混在一起。

## 外围市场 —— `core/global_market.py`

覆盖美股指数（道指/纳指/标普）、美股龙头（苹果/微软/英伟达/谷歌/亚马逊/特斯拉/Meta）、
港股（恒生/国企指数 + 腾讯/阿里/美团/小米/京东）、外汇（美元人民币/欧元美元/美元日元/英镑美元/澳元美元）、
商品（纽约金/银/原油/伦铜 + 沪金/螺纹钢）、日经与欧洲指数。

**GRAI · 全球风险偏好指数** —— 把分散的外围涨跌压成一个标量：

```
z_i  = 涨跌幅_i / 典型日波动_i          按各市场波动特性标准化
GRAI = 100 · tanh( Σ w_i · z_i + 0.15·(美股52周分位 - 0.5)·2 )
```

| 成分 | 权重 | 逻辑 |
|---|---|---|
| 美股 | +0.34 | 全球风险资产定价锚 |
| 恒生 | +0.20 | 与 A 股联动最紧 |
| 日经 | +0.10 | 亚太风险偏好 |
| 美元人民币 | -0.16 | 人民币贬值 → 外资流出压力（反向） |
| 黄金 | -0.10 | 避险资产，涨 = 风险偏好下降（反向） |
| 原油 | +0.06 | 需求侧指标 |
| 伦铜 | +0.04 | 工业需求 |

再输出「对 A 股的传导判断」和具体信号（美股大跌 / 黄金避险 / 人民币贬值 / 油价异动）。

单标的分析分两条路：有 K 线的（美股/港股/期货）走**当日 · 趋势 · 动量 · 位置 · 风险**五维评分；
只有快照的（外汇、部分指数）用快照位置分位降级评估。
注意：外围标的的标签是「强多/偏多/中性/偏空/强空」，不要和 GRAI 的 Risk-On/Risk-Off 混用。

## 基金 —— 主动与被动分开评价 `core/fund.py`

这是本项目第二个核心。**主动基金和被动基金的优劣标准完全不同**，用同一把尺子量是错的。

### 类型判定

```
场内ETF / LOF / 指数 / ETF联接 / 指数增强   → 被动（或半主动）
主动股票型 / 主动混合型 / 主动债券型 / QDII  → 主动
```

判定依据：名称关键词（「ETF」「指数」「增强」「联接」「股票」「混合」）+ 代码段
（沪市 510/511/512/513/515/516/517/518/560-563/588/589，深市 159/160-169）。

### 基准匹配

从基金名称里提取跟踪标的，映射到新浪指数代码，**按具体到宽基的顺序匹配**：

```
白酒→399997  证券公司→399975  医疗/医药→399989  银行→399986
```

踩过的坑：基金全称里几乎都有「证券投资基金」，如果不先剔除这个词，
「证券」关键词会把每一只基金都匹配成证券指数。所以匹配前要先洗掉通用词。

### 评价公式

**被动基金**看「跟得像不像」：

```
P = 0.40·tanh((2.0 - 年化跟踪误差)/1.5)
  + 0.30·tanh(年化超额/3)
  + 0.30·tanh((夏普-0.5)/1.0)
```

**主动基金**看「有没有超额能力」：

```
A = 0.40·tanh(Jensen Alpha/5)
  + 0.30·tanh(信息比率/1.0)
  + 0.30·tanh((夏普-0.5)/1.0)
```

**绝对收益约束**：相对基准再好，只要还在亏钱就不能算「良好」。
年化收益为负时按 `max(0.25, 1 + 年化收益/10)` 打折。

### 指标

区间/年化收益、年化波动、最大回撤、夏普、索提诺、卡玛、胜率、
跟踪误差、信息比率、Beta、Jensen Alpha、与基准相关性。

### 风格判断

用「与基准的相关性 + 跟踪误差」反推这只基金到底有多主动：

| 相关性 | 判定 |
|---|---|
| > 0.95 且 TE < 2.5% | 高度跟踪，本质是指数化产品 |
| > 0.85 | 较强跟踪，在基准上做有限偏离 |
| > 0.60 | 部分跟踪，有一定主动偏离 |
| ≤ 0.60 | 主动偏离明显，真正的主动管理 |

还会反过来校验产品定位：被动产品如果相关性很低 → 提示「跟踪误差偏大」；
主动产品如果相关性很高 → 提示「伪主动、风格漂移」。

## 多周期分析

日 / 周 / 月 / 分钟线**各自独立走完整分析** —— 不是只换一张图。

```
scale=240   → 拉 620 根日线   → 缠论 / 形态 / 主力阶段 / 评分 全部基于日线
scale=1200  → 拉 400 根周线   → 同样全部基于周线
scale=7200  → 拉 240 根月线   → 同样全部基于月线
scale=5/15/30/60 → 分钟线
```

**唯一的例外是筹码**：始终基于日线。因为持仓成本是日频换手一天天累积出来的，
拿周K去算筹码，等于把 5 天的成交当成一根，衰减系数全错。

风险维度做了**周期归一化**：

```
NATR_adj = NATR / √period_days        （日=1，周=5，月=21）
```

不做这一步的话，同一只股票换个周期就从「低风险」变成「高风险」——
周振幅天然是日线的 √5 倍，直接比绝对值没有意义。

数据不足 40 根时自动回退到日线（新股、停牌、部分指数月线太短都会触发），
前端会把周期按钮的高亮同步到实际使用的周期。

## 为什么不做成在线版

试过，不行。三个硬约束：

1. **没有 CORS 头** —— `hq.sinajs.cn` 和 `money.finance.sina.com.cn` 的响应里
   都没有 `Access-Control-Allow-Origin`，浏览器 `fetch` 直接被拦。
2. **Referer 白名单** —— 把 `Referer` 换成 `https://xxx.github.io/` 请求行情接口，
   新浪直接返回 `Forbidden`。所以连 `<script src>` 这种 JSONP 式绕法也走不通。
3. **K 线接口是 JSON 不是 JSONP** —— 就算行情能用 script 标签拿，
   K 线也只能 `fetch`，同样被 CORS 挡死。

结论：必须有一个本地进程做代理。这个进程就是 `server.py`。

## 手机上怎么用

先划重点：**把文件夹发到手机上点 `启动.bat` 是跑不起来的**。`.bat` 是 Windows
批处理脚本，安卓/iOS 没有 `cmd.exe`，手机也没有现成的 Python 环境。

手机上有两种玩法，按需要选：

| | 方式一：电脑当服务器 | 方式二：手机独立跑 |
|---|---|---|
| 依赖电脑 | 必须开机 | 不需要 |
| 网络 | 必须同一 WiFi | 有网就行（4G/5G 也可以） |
| 适用 | 在家用，最省事 | 出门在外、随时看 |
| 平台 | 安卓 / iPhone 都行 | **只有安卓**（iPhone 无解，见文末） |

---

### 方式一：电脑当服务器，手机当显示器

1. 电脑双击 `启动.bat`（默认已监听 `0.0.0.0`，即所有网卡）。
2. 控制台打印「手机访问：`http://192.168.x.x:8765/`」，记下来。
3. 手机连**同一个 WiFi**，浏览器打开这个地址。

- 电脑必须开着且不能休眠，服务停了手机就打不开。
- 打不开先看 Windows 防火墙是否放行 Python（专用网络）。
- 公司/学校 WiFi 常开「AP 隔离」，设备互不可见 —— 开手机热点、让电脑连上去即可。
- 只想本机用：设环境变量 `JYHQS_HOST=127.0.0.1` 再启动。

---

### 方式二：安卓手机独立运行（不依赖电脑）

原理：这个项目**零第三方依赖，全部是 Python 标准库**，所以安卓上装个 Termux
（一个 Linux 终端 App）就能直接跑 `server.py`，数据照样实时抓新浪，分析照样算。

#### 第 1 步：装 Termux

**别在 Google Play 装**（那个版本早已停止更新，装不了包）。从这两个地方之一装：

- F-Droid：https://f-droid.org/packages/com.termux/
- GitHub Releases：https://github.com/termux/termux-app/releases
  （选 `termux-app_v0.118.x+github-debug_universal.apk`）

想省事可以顺手把 **Termux:API** 也装上（同一来源），装完能自动拉起浏览器。

#### 第 2 步：把安装包传进手机

电脑上跑：

```bash
python termux/build_zip.py
```

会在桌面生成 `jyhqs-mobile.zip`（约 117 KB）。用微信/QQ/数据线传到手机，
**存到「下载 / Download」目录**。

#### 第 3 步：Termux 里三行命令

打开 Termux，逐行粘贴回车：

```bash
termux-setup-storage
pkg install -y unzip
unzip -o ~/storage/downloads/jyhqs-mobile.zip -d ~ && bash ~/jyhqs/termux/install.sh
```

- 第一行会弹「允许访问文件」—— 点允许。
- 第三行跑完会自检项目、装 Python、写一条快捷命令。

> **网速慢（只有几 KB/s）先换源，否则装 Python 要等半小时以上。**
> 看到 `Fetched xxx kB in 31s (8xxx B/s)` 这种速度就说明要换源了：
>
> ```bash
> sed -i 's@^\(deb.*stable main\)$@#\1\ndeb https://mirrors.tuna.tsinghua.edu.cn/termux/apt/termux-main stable main@' $PREFIX/etc/apt/sources.list && pkg update
> ```
>
> 或者跑交互式的 `termux-change-repo`，方向键选中后选 TUNA（清华）。
> 也可以在跑 install.sh 时直接带参数：`JYHQS_MIRROR=tuna bash ~/jyhqs/termux/install.sh`

#### 第 4 步：启动

以后每次用：打开 Termux → 输入 `jyhqs` → 回车。

浏览器会自动打开 `http://127.0.0.1:8765/`。没自动开就手动输这个地址。
第一次进页面要 2~5 秒抓数据，等一下。

#### 手机上的几个坑（必看）

| 现象 | 原因 | 处理 |
|---|---|---|
| 切后台一会儿就断 | 安卓把 Termux 杀了 | 系统设置 → 应用 → Termux → 电池 → 选「不限制」 |
| 锁屏后不动了 | CPU 休眠 | `start.sh` 已自动加 `termux-wake-lock`，别手动清掉 Termux |
| `unzip: command not found` | 没装 unzip | `pkg install -y unzip` |
| 中文文件名乱码 | 与手机版无关 | 手机版包里全是 ASCII 文件名，不会出现 |
| 流量跑得快 | 每 5 秒抓一轮行情 | 正常，一天几十 MB；想省流量改 `config.POLL_INTERVAL` |

#### 想要桌面一键启动

装 **Termux:Widget**（同一来源），在手机桌面放一个 1×1 小组件，指向
`~/.shortcuts/` 里的脚本：

```bash
mkdir -p ~/.shortcuts
printf '#!/data/data/com.termux/files/usr/bin/bash\nbash ~/jyhqs/termux/start.sh\n' > ~/.shortcuts/交易很轻松
chmod +x ~/.shortcuts/交易很轻松
```

之后点桌面图标就直接起服务。

### 为什么不支持 iPhone

iOS 不允许任何 App 常驻运行本地服务器，也没有可以装 Python 并长期跑脚本的免费环境：

- **a-Shell**：能跑 Python，但受限沙箱，`http.server` 起不来、`ssl` 也不全。
- **Pythonista**（付费 ¥68）：能跑，但**切到后台立刻被挂起**，回来还得手动重开。

结论：iPhone 上只能走「方式一」，把电脑或一台常开的设备当服务器。

想彻底摆脱电脑、外网也能用，就得把 `server.py` 部署到一台有公网 IP 的机器上，
再用 Nginx 反代 + HTTPS；纯静态托管（GitHub Pages 之类）依然不行，原因见上一节。
